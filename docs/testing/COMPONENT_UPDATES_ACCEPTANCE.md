本轮基于 `fix/first-run-ssh-access` 的 `c15b3afd9ab46be193954688e578560319e7bfde`，保留远端 main 的 Dashboard V003。长期自动更新归 `dev/core`。本轮使用现有环境分支联调，因为当前 `dev/core` 不含三项 Bundle 资源。使用隔离的测试 Bundle ID、单次本机测试密钥和环回 HTTP。未修改生产信任根或真实安装。协议和发行流程见[更新文档](../NATIVE_UPDATES.md#component-update-schema-3)。

组件独立变化使用隔离标记文件，原始三项运行归档和二进制字节未改动。版本对使用实际签名 arm64 App。初始尝试的真实 Sparkle 目录链接暴露了扫描器跳过子目录的问题，随后修复并补充回归。外置卷隔离安装的 Helper 卡在创建事务目录，本机验收改用用户缓存目录内的隔离安装。未修改系统权限。

Core-only 从收到 ZIP 请求至确认启动约 **9 秒**，已确认的单组件轮约十余秒。Proton 单组件轮按 0.5 秒间隔采样隔离安装与共享测试请求缓存，两处基线之上的峰值为 **1,201,196 KiB**。HTTP 下载临时区不在此采样范围。初版 Helper 在旧 App 退出后曾留有请求缓存。加入身份绑定清理后，Runtime 和多组件轮不再增加请求缓存目录。未主动清理早期证据。

Core-only 签名测试 App 的逻辑大小为 **614,695,000 B**。其完整 ZIP **574,082,203 B**，DMG **577,637,507 B**，Core ZIP **25,497,616 B**，下载制品节省 **95.56%**。请求数和字节数不含少量签名清单及发布列表。签名完整 App 使用三项未改动的内置资源。两次纯 Core 情形下，UI 与 Swift 逻辑变更均由同一 Core 包承载。没有分别制作 UI-only 和 logic-only 两份制品。

## 自动化与剩余工作

- 发布服务测试覆盖单组件、多组件、完整复用、本地指纹不匹配、较旧的基础构建、全量优先、签名、哈希与中断处理。ZIP 测试覆盖路径、符号链接和大于 2 GiB 的稀疏文件。大于旧上限的 **574,082,635 B** 全量 ZIP 已在实际回退中通过。
- 错误签名不进入全量备用。已签名的制品按长度、哈希及路径校验，Helper 继续使用原有事务记录、旧版备份、启动确认及交换恢复。实际磁盘写满、临时目录不可建、强制关机或重启中断均为 NOT_TESTED。下载中断、损坏摘要和恶意路径的结果来自自动化夹具。没有连接生产更新 feed。
- Release 与 CI 的受控资源禁用规则保留。组件工具拒绝私有输入进入正式制品，隔离环回 transport 仅编译在 Debug 并限测试 Bundle ID。中英文设置页与更新后总览、首次配置入口均通过 App 交互复核。三个组件仍未批准公开分发。
- Guest 任务仍开放。只读探测确认目前仅 FX 1.9.9 独立副本被运行实例持有，SSH 前置监听返回 banner。之前认证后检测的 TIMEOUT 根因未确认。真实缺失安装、离线、两次重启和游戏验收未从此次 App 更新推断。见[环境验收](RF_FEX_BUNDLED_DEPLOYMENT_ACCEPTANCE.md)。
