## Optional credential remembering — 2026-11-03

`HD2_NATIVE_APP_CREDENTIAL_REMEMBER_v1.0.0` supersedes the earlier blanket prohibition on Native SSH Keychain persistence. `SessionCredentialManager` uses the macOS login Keychain service `com.lsjop.helldivers2fx.native.remembered-credentials.v1`, with separate SSH/sudo accounts derived from the target/config-revision hash. No App-managed encryption key or credential file is introduced. Only non-secret target/remember/rejection metadata enters preferences. A cached SSH master, a passwordless sudo command or an unchallenged sudo timestamp does not prove an entered password; the backend emits persistence proof only after an actual password challenge succeeds. Bad stored credentials stop reuse, including after restart. Storage access errors do not become FX failures or downgrade to plaintext storage. A dedicated `test_guest_sudo` operation validates the selected identity without starting the game or changing Guest configuration. Clear operations require UI confirmation and apply only to this new service; signing, Sparkle and legacy-script Keychain entries are unchanged.

Verification uses fictional credentials: 25 Swift lifecycle/storage/redaction checks, 17 Python credential/transport/proof checks, 27 migration checks, 24 service checks, and separate-process write/read/delete against a unique temporary real Keychain service. Locked/unavailable-store fallback and noninteractive automatic reads are covered by injected vault faults. The final bundled App smoke passed all 23 capability entries, 10 retained locale catalogs and consent/root rejection. The original successful game environment and archived launch command are unchanged. FX was not running at the final read-only observation; no real-password cold launch is inferred from these tests.
